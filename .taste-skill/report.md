## 设计方向

使用用户指定的 Taste Code / design-taste-frontend app-screen 流程。方向为 **Framed Sheet**，seed **877199236**，无重新抽签。采用新云品牌的低饱和绿灰外框、白色工作区，保留橙色标记与中文系统字体；没有新增网络字体或构建依赖。

选用这一方向是因为本产品用于长时间编辑客户需求、核对库存和准备提案，工作内容需要比导航更突出。抽到的 graph-builder 屏幕模板不适用于现有表单，因此保留现有需求表单和媒体结果区，以同一 Framed Sheet 外框组织，没有添加图节点。

产品特有的元素是“客户需求 → 覆盖依据 → 媒体库存 → 报价条件”状态行。状态来源于当前需求、地标、研究依据、库存和实际计算结果，每项可进入对应工作页。

## 页面要回答的问题

| 页面 | 首要问题 | 设计处理 |
| --- | --- | --- |
| 提案工作台 | 这份提案准备到哪里，还缺什么？ | 左侧需求、右侧准备状态与库存，缺口提示可以进入数据中心 |
| 媒体资源库 | 哪些原始记录符合筛选条件？ | 搜索、媒体筛选、清晰行列、分页、详情和完整导出 |
| 覆盖分析 | 有哪些历史证据和已核实位置？ | 报告指标、可折叠报告目录、门店与研究依据 |
| 我的提案 | 是否已形成可导出的有效组合？ | 数据不足时明确说明；有效时保留报价、排期和导出 |
| 数据中心 | 数据来自哪里，如何补齐和备份？ | 导入操作、可折叠来源目录、改名记录和备份操作 |

## 交互与数据边界

- 导入直接填入现有需求表单，允许修改后一次整体确认。待确认时依旧阻止最终方案导出。
- 真实库存 431 条、原表空位 888 辆、2023 年 5 月报告 26 份保持原样；未添加示例数据。
- 价格、可售日期、税费、制作费和坐标未提供时继续保持空白。
- 未提供坐标时以简短任务入口替代大面积空地图。已有坐标仍可以展示参考点。
- 库存清单保留用户要求的分页和折叠，导出继续包含完整数据。
- 材料检索置于顶部，支持 Esc 收起、Enter 重新显示；平板弹层校验在视口内。
- 历史报告和来源文件保留所有记录，通过原生折叠与区域内滚动控制页面长度。
- 主标题 24px，正文与数据 14px，说明 12px，等级标记 11px；表格数值使用等宽数字、右对齐。
- 平板双列表单、手机底部导航与局部横向滚动，保留每个字段。

## 验证结果

- 42 项数据、解析、分页和服务器自动测试全部通过。
- 四组浏览器检查通过：真实数据、分页与搜索、需求导入、三端 UI。
- 五个页面在 1440 / 768 / 390 宽度共 15 组布局检查通过，没有整页横向溢出、低于 11px 的已检查可见文字或浏览器运行错误。
- 人工查看桌面、平板、手机截图，修正检索弹层定位、跳转链接焦点样式与长目录高度。
- Taste Code 静态 lint：0 FAIL，2 WARN。
- shadow 警告保留：阴影仅用于浮动搜索结果、弹窗、提示、焦点环，以及手机冻结列的分隔线；固定内容卡片没有阴影。
- em-dash 警告保留：用于未提供数值的占位以及投放日期范围，不是装饰性文案。
- 用户明确要求短清单分页，因此保留这一交互，优先于 skill 的短列表分页偏好。

官方 inspect.mjs 的 CDP 浏览器启动在当前 Windows 环境直接退出；默认浏览器、指定 Edge 和兼容参数均未解决，因此没有声称通过该检查。替代验证使用可运行的 Playwright + Edge，生成完整截图和布局 JSON。截图位于 .taste-skill/after/，检查脚本是 tests/browser-ui.mjs。

没有新增待替换的示例内容，没有发布到外部服务器。部署方式仍是原来的 Node.js server.mjs，无前端构建步骤。
