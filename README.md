## 运行

需要 Node.js 20 或以上，无 npm 生产运行依赖，无前端构建步骤。浏览器回归使用已声明的开发依赖 Playwright。

    npm start

或直接运行 `node server.mjs`。浏览器打开 http://localhost:3000 。服务仅监听本机 127.0.0.1。

测试：`npm test`。测试覆盖原表逐行核对、空值保留、文件改名哈希、导入导出、报价约束、列表分页、材料检索与 HTTP 接口。浏览器交互回归：启动服务后运行 `npm run test:browser`。先执行 `npm install` 安装开发依赖。Windows 默认使用已安装的 Edge，其他系统使用 Playwright Chromium；可运行 `npx playwright install chromium` 并设置环境变量 `PLAYWRIGHT_CHANNEL=chromium`。测试文件由脚本枚举，不依赖 shell 展开通配符。

媒体组合栏与刊例测算：`node --test tests/mix-panel.test.mjs`；浏览器回归 `node tests/browser-mix-panel.mjs`。

比赛材料落地：`node --test tests/brief-email-sample.test.mjs tests/handoff.test.mjs tests/closing-report.test.mjs tests/selection-table.test.mjs`；浏览器回归 `node tests/browser-closing-report.mjs`。

商务条款与地址筛选：`node --test tests/commerce.test.mjs`；浏览器回归 `node tests/browser-commerce.mjs`。

施工排期引导：`node --test tests/handoff.test.mjs`；浏览器回归 `node tests/browser-construction.mjs`。

刊例填入：浏览器回归 `node tests/browser-rate-prefill.mjs`、`node tests/browser-quick-quote.mjs`。

报价文件：`node --test tests/quote-file.test.mjs`；浏览器回归 `node tests/browser-quote-file.mjs`。

界面改版：浏览器回归 `node tests/browser-ui-refinement.mjs`、`node tests/browser-redesign.mjs`。

## 功能

### 1.10 报价文件、右栏只读与导出入口

- **移除假设书页面**：导航不再有「假设书」，提案页也不再生成七要素/自检/假设回应；假设书由团队自己维护，应用只负责需求、组合与报价。
- **双媒体配比只在左侧修改**：右侧媒体组合栏改为只读——显示目标/实际占比、偏差与达成状态，不再提供滑杆、容差和硬约束控件；所有调整在「客户需求 → 媒体配比」完成。
- **报价文件默认 07 刊例**：报价直接按当前报价文件的区间价（中位）计算。需求表单「商务与执行」与数据中心都有“报价文件”卡片，可上传新的 .xlsx / .csv 报价文件替换（需包含“刊例价”“发布期”列），也可一键恢复默认 07-媒体刊例价.xlsx；第一次进入默认使用 07。
- **切换发票不再让报价消失**：专票/普票税率或依据缺失只标“发票条款待补”，不再阻断配单和金额；补齐依据后自动用于价税拆分。
- **提案导出位置**：组合生成后，「推荐预览」顶部和「我的提案」顶部都会出现固定的“提案导出”栏：交互 HTML、Excel、CSV、结案报告 PPTX、打印/PDF、报价设置。文件下载到浏览器默认下载目录；未生成组合时「我的提案」会提示先生成组合。

验收：`tests/quote-file.test.mjs`、`tests/browser-quote-file.mjs`、`tests/browser-mix-panel.mjs`、`tests/browser-commerce.mjs`。

### 1.9 需求表单与工作台可读性改版

按参考工作台（填条件左栏）的使用方式，调整需求填写与工作台切换：

- **投放预算可直接填写**：预算区改为数字输入框，可与滑杆、100/200/300/400/500 万快捷档双向同步；支持 100–500 万之间的小数（如 250.5 万），失焦或回车后重算。
- **标题与板块有颜色区分**：页面标题左侧加蓝色标记；需求表单拆成“客户与目标 / 预算与档期 / 媒体与配比 / 商务与执行 / 补充需求”五段，每段有独立色条、编号与标题色；工作区卡片标题、字段集标题统一为深蓝，选中标签为蓝色。
- **客户投放需求参考站布局**：左栏加宽到 340px（1600 以上 356px）并保持 sticky，行业改为可点选 chips（隐藏 select 继续兼容导入逻辑），字段更紧凑，补充需求折叠，长表单更好扫读。
- **组合目标与约束直接键入**：全站数字输入隐藏上下箭头（`appearance: textfield`），约束、产能、比例、税率等直接输入，不再需要点小箭头。
- **切换标签后主体优先**：顶部标签栏 sticky；非“推荐预览”页把媒体组合栏移到主体内容之后，点击“组合调整 / 施工排期 / 监测交付 / 空间与规则”后主体紧跟标签，不再被组合栏压到下方。

验收：`tests/browser-ui-refinement.mjs`（预算直填/滑杆/快捷档同步、行业 chips、分段配色、标签内容顺序、移动端抽屉）；`tests/browser-redesign.mjs`（六页面三端布局与交互）。

### 1.8 直接用 07 刊例价报价

`data/07-媒体刊例价.xlsx` 里是**区间价 + 发布期 + 制作费区间**（例如“约 5–7 万 / 1 月 / 约 5–10 千”）。按客户要求可以直接拿它报价，现在提供三种入口：

- **一步报价**（空状态主按钮“直接用 07 刊例价报价”）：点一下即按区间中位生成报价；档期未填时按 2027 Q1 试算（可在左侧修改），不弹窗、不需逐项确认。价格来源、档期与“非成交价”标识会写进组合栏、提案与导出物。
- **调整测算假设**：需要换取值时可选区间下限 / 中位 / 上限、地铁制作费假设、渠道与默认档期，再生成。
- **单资源填入**：资源详情 → 补充 / 修改已核实报价条件 → 从 07 刊例区间填入单价、制作费、计费口径（1 月 → 自然月）与来源；仍须补齐可售日期与含税口径后保存，不自动写入库存。

导出与提案会标注“刊例价口径（区间中位）、非成交价”；直接把这本区间刊例当精确价导入仍会被拒绝并提示改用上述入口。

验收：`tests/browser-rate-prefill.mjs`、`tests/browser-quick-quote.mjs`（一步生成组合与提案、默认 Q1 档期、无弹窗、未保存不改库存）。

### 1.7 施工排期填写简化

原施工条件一次要求填写 4 个日期、产能、备用夜晚、依据、停工日与两个确认勾选，确实偏重。现在改为**三步引导**，并把建议值、示例和一键条件放到表单里：

- **① 班组产能**：公交/地铁每夜产能、备用夜晚、产能依据，均带示例占位（例：4 / 例：2 / 例：1 / 班组确认单）。
- **② 施工时间窗口**：四个日期全部改为**下拉选择**（显示“2026-12-25（周五）”这类日期 + 星期），上刊窗口限定在投放开始日前 30 天内、下刊窗口限定在投放结束后 30 天内，避免手输格式错误；按档期自动预填建议值并标注“建议日期，请核对”，也可点“按档期填入建议窗口”重新填入。每段只需核对 4 个日期并勾选进场许可。
- **③ 停工日与确认**：没有固定停工日可留空；勾选整体确认后保存。
- 保存后**自动拆批生成施工任务**，表格不需要逐条新建，通常只需补责任方；任务表里的“施工日期”也是下拉选择（只列出该窗口内可施工的日期，已扣停工日），改日期或数量会标记为人工调整。保存成功的提示会直接说明生成了多少条任务。
- 刊例测算模式下额外提供“载入演示施工条件”一键按钮（4 台/夜、2 口/夜、1 晚备用、建议窗口、演示依据），字段明确写“刊例测算”，真实项目需替换。

验收：`tests/handoff.test.mjs` 增加建议窗口/演示条件生成测试；`tests/browser-construction.mjs` 覆盖三步表单、建议日期、一键条件、自动生成批次与 1440/768/390 布局。

### 1.6 商务条款、配比与必须经过的地址

对照参考工作台的 Left rail 条件项补齐五项，全部进入现有需求表单、组合引擎、报价单和导出物：

- **媒体配比**：双渠道时可直接填公交 / 地铁两个百分比（自动互补、合计须为 100），并可设容差与“硬约束”；单渠道固定 100%。按资源**数量**口径写入既有组合约束，与媒体组合栏的滑杆共用同一目标。
- **客户折扣**：以“折”为单位输入（如 8.5 折），仅作用于媒介费；低于已核实审批线时在表单内提示审批依据要求，并进入报价口径与提案封面。
- **结算发票**：增值税专票 / 增值税普票 / 不开票；专票提示需客户提供四项开票信息。
- **税率**：6 / 9 / 13 / 5 / 3 / 1%，必须填写核实来源。税率只用于对含税合计做**价税拆分展示**（税额 ≈ 含税 × r/(1+r)），不重复加税、不改变应付金额。
- **必须经过的地址**：地址名称 + 已核实经纬度 + 坐标系 + 500 m / 1 km / 2 km / 3 km 或自定义半径；按已核实的同坐标系参考点直线距离硬性筛除不满足的资源，缺少可核实关系时明确阻断并给出原因，不做地理编码。

验收：`tests/commerce.test.mjs`（7 项）与 `tests/browser-commerce.mjs`（浏览器交互与 1440/768/390 布局）。详见 [商务条款与地址筛选](商务条款与地址筛选.md)。

### 1.5 比赛材料落地：4A brief、上下刊卡点、结案报告与提案档位

依据用户提供的比赛业务材料（`比赛文档/`，不随交付包发布）落地了四项能力，详见 [比赛文档落地与结案报告](比赛文档落地与结案报告.md)。

- **4A 客户 brief 解析**：支持 `客户「某国际品牌」` 这类匿名客户名、媒体数量、监测与验收要求、结算与合同要求、客户回复期限；非 2027 年档期会明确说明“不在赛题范围、未自动填入”，LED / 户外大牌等当前不支持的媒体会明确提示而不是静默保留旧渠道。新增字段进入需求表单的“补充需求”区并随导入确认记录保存。
- **上下刊卡点与风险**：依据《上下刊流程卡点说明》在施工排期视图中给出 8 项自动检查（夜间窗口、单晚产能、备用夜晚、停工日、定稿审批前置、进场许可、外包监拍延迟、交接依据），并提供四类（客户端 / 外部客观 / 内部运营 / 外包供应链）人工风险登记；检查与风险写入 Excel/独立 HTML 的“上下刊卡点”工作表。
- **结案报告 PPTX**：按《M5-结案报告样本》结构生成 8 页结案报告（项目概览、内容概况、分周期执行、资源清单、监测与验收、效果与口径、后续建议、数据来源）。只使用本项目真实拥有的数据；没有去重人流模型时不写触达、CPM、转化与播放频次，并在页面明确说明。刊例测算模式下自动加“刊例测算、非成交价”标识。
- **提案线路甄选表与三档采购方案**：提案页新增按渠道分表的线路/点位甄选表（含合计行），以及公交 100 / 150 / 200 辆、地铁 10 / 20 / 30 口的三档采购方案测算；档位按当前已选资源的单价与可售量顺序补齐，并注明“不是已锁定资源或最终报价”。

### 1.4 媒体组合栏与刊例测算

提案工作台右栏新增常驻「媒体组合栏」：公交 / 地铁分表的条数与台/口数、逐资源 `− / +` 配量、双媒体数量配比（目标占比 + 容差 + 硬约束，写回既有组合约束）、按渠道小计的媒介费、报价构成（媒介费 / 制作费 / 执行费 / 监测费 / 含税合计 / 预算余量）、约束校验 chip 与“指定但当前不可满足”的原因。改数量只写按稳定编号保存的人工选择，不改原表空位；切换五个工作视图时组合信息不丢失。

默认 1292 条真实库存没有精确价和可售期，因此默认仍不报价。需要现场查看完整流程时，可在组合栏空状态显式“按刊例区间生成测算稿”：只对缺失的价格 / 可售期 / 制作费 / 税口径补充测算假设（价格取已公开刊例区间，公交按原表等级、地铁接口 L1/L2/L3 依次映射 A++/A+/A+），已人工核实的记录不被覆盖，原始库存记录也不被改写。演示状态在顶部提示条、组合栏、提案水位线与 Excel / CSV / 独立 HTML 中均带“刊例测算、非真实成交价”标识，可随时退出并恢复严格口径。详见 [媒体组合栏与刊例测算](媒体组合栏与演示测算.md)。

### 原有功能

1. 五个指定行业，100–500 万预算滑杆与 100 / 200 / 500 万快捷切换。
2. 仅提供公交车辆、地铁站站口两类渠道，可单选或组合；2027 年内支持年度、季度、月度、自定义日期，以及全部时间或分段投放；包含制作费的含税预算约束。
3. 规则配单：行业场景、地标邻近、媒体等级、区域多样性与递减收益。确定性启发式，不承诺全局最优。
4. 库存 CSV / XLSX 导入，字段识别、预览、错误阻断、多工作表选择；价格表按编号或唯一等级匹配。
5. 工作台可查看逐资源全部报价缺口；资源详情可手工填写已核实的精确价格、制作费、28 天周期、含税口径、可售日期与核实来源。只保存到当前浏览器项目，不修改源表。
6. 门店 / 地标经纬度与半径管理、品牌研究证据登记。
7. 交互式 HTML 导出：单文件、无联网依赖、现场切换预算并重算明细与总价。
8. 真正的 XLSX 导出（投放清单、报价口径、品牌与地标依据、排除记录、投放排期）及防公式注入的 CSV。HTML、Excel、CSV 均保留每段日期。
9. 草稿本地保存、项目 JSON 备份与恢复、打印 / PDF、移动端布局、路演模式。
10. 可选真实模型接口：只生成策略草稿，永不参与库存或金额计算。
11. 库存与推荐清单支持收起 / 展开、首页 / 末页及前后翻页；工作台默认每页 5 条，资源库与提案默认每页 10 条，可切换 5 / 10 / 20 条。搜索与类型筛选作用于完整清单，导出不受当前页影响。
12. 各页面顶部提供相关材料搜索，检索已导入库存、历史人流报告、来源文件名及调研摘要。支持类型筛选、每页 6 条结果和详情查看；输入为空时自动收起结果，不检索未导入文档或外部网络。

### 导入客户需求（自动填入，整体确认）

工作台「客户投放需求 → 导入客户需求」支持粘贴客户邮件 / brief，或上传 TXT、CSV、XLSX。可下载空白 CSV 模板，用 Excel 填写后导入。模板没有预填客户或金额。

1. 粘贴原文或选择文件。TXT / CSV 上限 1MB，XLSX 上限 10MB；单份需求最多 50,000 字符。旧版 XLS 请另存为 XLSX，Word / PDF 请先复制文字。

3. 本地规则提取品牌、行业、预算、媒体、投放日期、目标、人群、区域、门店要求和备注。保留原文依据；单位不明、金额范围、重复冲突和不完整日期不自动选值。不是外部 AI 模型解析。
4. 识别结果直接填写到现有行业、品牌、预算、媒体、日期和目标控件，标注「待整体确认」，没有逐项勾选弹窗。可直接修改；补充信息在同一表单的折叠区中编辑。缺失或无效字段保留原值并提示。
5. 最后点击一次「确认需求并生成方案」。系统检查必填内容后记录整体确认，再按现有库存计算推荐。待确认草稿可刷新恢复、查看原文或撤销回到导入前；确认前不生成可导出的正式提案。现有库存缺少价格等报价条件时仍不会生成报价。

预算以「万元」为单位，范围 100–500；日期须在 2027 年内。导入不调整库存或刊例价格，也不替客户锁定资源。待确认草稿与确认记录保存在当前浏览器并随项目 JSON 备份；原文不传给外部模型，XLSX 仅交由本应用现有接口解析。

交互回归：启动服务后运行 `node tests/browser-brief-import.mjs`。

## 报价模型

    投放天数 = 各段（结束日 - 开始日 + 1）之和
    计费周期 = 各段 ceil(该段投放天数 / 28) 之和
    单资源媒介费（分） = round(28天刊例价 × 计费周期 × 销售价格系数 × 100)
    单资源制作费（分） = round(制作费 × 100)
    行金额（分） = （单资源媒介费（分）+ 单资源制作费（分）+ 已确认单资源执行费（分））× 推荐数量
    项目总价（分） = 各行金额（分）之和 + 已确认项目监测固定费（分）
    配单前先预留已确认固定监测费；无可配资源时不虚计此费
    合计以整数分累加，展示与导出时除以 100

价格系数默认 1.00，只作用于媒介费；实际折扣由销售按培训口径输入。配单采用一次初排、按效用权重批量分配、余量择优补配的确定性启发式，不承诺全局最优；没有 10000 个单位的硬截断。合计不超过预算，剩余资源均不可负担或库存不足时保留余量。滑杆拖动只更新预算显示，松手 / change 后统一重算并保存一次。行业评分是规则分，不是效果预测。

年度、季度、月度按钮用于选择完整自然日期范围，不会把现有 28 天刊例价改成年价、季价或月价。分段间隔不计入投放天数，每段独立向上取整计费；分段不能重叠，最多 24 段。当前所有已选渠道、所有推荐资源共用同一组排期，库存须覆盖每一段。制作费沿用已录入的每资源一次口径，分段重复制作费用另行确认。

需求导入新增「投放渠道」和「投放日期」字段。例如日期文本可填写“年度 2027全年”“季度 2027年第一季度、第三季度”“月度 2027年3月、5月”，或以分号分隔多段完整起止日期。没有明确完整日期或明确周期的内容不会自动补齐。

## 红豆库存 API 同步（可选）

`scripts/hongdou-inventory.mjs` 只读拉取红豆管理系统的公交 / 地铁出入口库存，生成可直接在界面导入的 CSV。推荐用 OAuth2 登录（共用测试客户端 + 个人平台账号，不需要图形验证码）：

    $env:HONGDOU_USERNAME="平台用户名"
    $env:HONGDOU_PASSWORD="平台密码"
    node scripts/hongdou-inventory.mjs login
    node scripts/hongdou-inventory.mjs inspect
    node scripts/hongdou-inventory.mjs sync --start 2027-01-01 --end 2027-03-31

也可以不登录，直接设置 `HONGDOU_TOKEN`（后台 Network 里复制的 accessToken）跳过 OAuth2。账号、密码、令牌只在本机使用，可写进 `.env.local`（已忽略），不要提交 Git。

登录接口为 `POST /admin-api/system/oauth2/token`：HTTP Basic 使用共用客户端 `inventory-agent-test` / `inventory-agent-test`，表单 `grant_type=password` + 个人 `username` / `password`，请求头 `tenant-id: 1`。成功时 `code=0`，取 `data.access_token` 和 `data.expires_in`；账号密码错误时返回 `code=1002000000`。令牌缓存在 `data/private/hongdou/token.json`（gitignore，服务端不可访问），过期会按 `expires_in` 自动重新登录。

库存接口为 `GET /admin-api/orders/media-inventory/bus/page` 与 `.../metro/page`，共用请求头 `tenant-id: 1`、`Authorization: Bearer <accessToken>`；`pageNo` / `pageSize` 分页，`startDate` / `endDate` 是按日期查询的可售窗口，`lineName` / `keyword` 为可选过滤。返回业务包 `{code,data,msg}`：未登录时 HTTP 仍为 200，但 `code=401`、`msg=账号未登录`。

实测口径（2026-11-21，test3 账号）：

- 公交接口 `total=552`，但当前账号只返回 **431 条**（与 `data/公交车身媒体库存.xlsx` 的 431 条一致）；差额 121 条被接口过滤或账号不可见，需向新云确认数据权限。地铁返回 **861 条**，与赛题口径一致。
- 公交字段映射：`resourceId`→媒体编号（`HDBUS-<id>-<媒体规格>`），`lineName`→线路，`companyName`→运营公司，`mediaName`→媒体规格，`lineLevel`→等级（接口是数字等级，统一写成 `L1/L2/L3`；与源表匹配的 431 条沿用源表 A++ / A+ / S 等级，以保留刊例和报告关联），`freeCount`→空车数，`totalCount`→总车辆数，`contractCount` / `reservationCount` / `maintenanceForbiddenCount` / `renewPossibleCount` 分别对应合同车 / 预定车 / 保养影响 / 可能续约。
- 地铁字段映射：`lineName`+`exitName`→站名+出入口（如“上海南站 1号口”），`metroNumber` 为红豆编号，`stationAttr`↔换乘线路，`categoryTags` / `businessAreaName`→场景标签，`freeCount` / `totalCount` 同上。
- 同一个 `resourceId` 可能对应两种媒体规格（例如 312 的 955 路同时有“大三侧”和“车身三侧”），媒体编号会带规格后缀区分；接口分页会出现“短页”（100 条只返回 94 条）但后面仍有数据，脚本读到空页或达到 total 才停止。
- 接口**不返回** 28 天价、制作费、含税、计价天数、逐资源可售起止日期、经纬度和行政区名称。脚本默认把 `--start/--end` 查询窗口写进可售开始/结束，并在来源里标注“快照，非合同锁档”；严格场景用 `--no-dates` 留空，再用「补充已核实报价条件」或人工核实补档期与价格。`freeCount` 会随查询日期变化（实测同一公交在 2027 Q1 与 2026-11-21 的空车数不同），因此要按目标档期查询，不能拿今天的快照当 2027 档期。
- 一次 Q1 2027 同步结果：公交 431 条（可售 322 条，空车合计 1133，总车辆 2525）、地铁 861 条（可售 742 条）；CSV 经应用导入器 `normalizeRows` 校验 0 错误、0 警告，媒体编号唯一。公交匹配的 431 条同时沿用源表等级、3 条单报告人流值和 8 条报告关联。完整字段口径、文件哈希与导入步骤见 [红豆库存同步记录.md](红豆库存同步记录.md)。

输出 `data/红豆库存_both_<开始>_<结束>.csv`（公交 + 地铁合并）与 `data/private/hongdou/` 原始快照。首次导入用「替换全部」建立红豆基线，以后同步用「按编号更新，保留未提供记录」。库存接口通常不含 28 天价、制作费、税费和计价天数，这些字段留空，须按刊例或人工核实补齐；快照不等于资源锁定。

若返回字段与脚本内置映射不一致，先运行 `inspect` 查看「首条字段 / 样例」，再调整脚本里的 `ALIASES`。

这是 **Node.js 项目**，服务器面板选择「Node项目」。入口 server.mjs，启动命令 npm start，默认端口 3000。项目需要安装PDF.js生产依赖，前端不需要构建。

上传应用代码、lib 目录及 data/real-data.mjs。原始 Excel 和 Python 工具只有重新生成数据时需要。默认监听 127.0.0.1，通过服务器反向代理访问；公网部署仍需账号权限与访问控制。

HTTPS 反向代理推荐在 .env 填写 PUBLIC_ORIGIN=https://实际访问域名（可含端口，不含路径），必须与浏览器 Origin 完全一致，才能正常使用 Excel 导入 / 导出 POST 接口。另一种方式是在本机反向代理明确覆盖 X-Forwarded-Proto 时配置 TRUST_PROXY=true；仅信任回环地址传来的该头，不信任客户端任意转发头。保持跨站请求拒绝，不忽略协议。端口冲突会显示可读提示并以非零退出码退出。

执行 npm run package 会在 dist/ 下新建带时间戳的干净交付目录，包含应用、原始资料、可复现的数据构建脚本、测试与文档；排除 .env、.tools、node_modules、.git、Python 缓存、截图与 test-results。不会删除本地工具或原始业务资料。部署仅需生产文件，执行 npm ci --omit=dev 安装生产依赖。

## 文件结构

- `index.html` / `styles.css` / `app.js`：响应式工作台，无框架依赖。
- `lib/mix-panel.mjs`：常驻媒体组合栏（配比、配量、报价构成、约束校验）。
- `lib/demo-mode.mjs`：显式刊例测算的派生假设，不写入库存记录。
- `lib/pptx.mjs` / `lib/closing-report.mjs`：零依赖 PPTX 写入器与结案报告内容组装。
- `lib/selection-table.mjs`：提案线路甄选表与三档采购方案测算。
- `lib/operations.mjs`：施工、监测与上下刊卡点检查（含风险登记）。
- `lib/engine.mjs`：报价、预算分配、CSV、字段映射和校验。
- `lib/xlsx.mjs`：受限 XLSX 读取及真实 XLSX 生成。
- `lib/export.mjs`：独立 HTML 与报价工作表。
- `lib/state-validation.mjs` / `lib/quote-ui.mjs`：恢复校验与人工核实条件入口。
- `lib/review-export.mjs`：明确标注非报价的资料核对稿。
- `scripts/run-tests.mjs` / `scripts/package.mjs`：跨平台测试枚举与干净交付目录。
- `scripts/hongdou-inventory.mjs`：可选的红豆库存 API 同步（公交 / 地铁分页拉取并生成导入 CSV）。
- `data/real-data.mjs`：由用户源文件生成的库存、历史画像和来源清单。
- `scripts/build-data.py`：只读解析原始 XLSX / XLS 并生成前端数据。
- `server.mjs`：静态服务、Excel API、可选 AI 代理。
- `tests/`：约束、文件、注入防护、离线提案、HTTP 测试。
- `ONE_PAGER.md`：提交用一页纸，团队姓名待填写。

## 边界与部署

数据保存在本机浏览器 localStorage，JSON 备份含库存与研究摘要，请按比赛资料保管。不接入其他真实企业系统。无账号体系、审批流、多人协作、自动库存占用或跨设备同步，面向本机比赛演示。公开部署前需要补齐认证、权限、限流与合规存储。

刊例测算模式是显式假设：其中的价格、可售期与制作费不是企业核实数据，页面与导出物均带标识，退出后恢复严格口径；不能把演示数字当成成交价或资源锁定。

未提供坐标时地图保持空白。录入坐标后仅展示参考点，不绘制虚构道路或公交轨迹；不转换坐标系，不去重历史人流，不计算实际路网。
